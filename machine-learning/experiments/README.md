# experiments/(記録者)

シナリオ・評価計画・パラメータを選んで評価し、結果を記録します。
「どの設定で、どんな結果が出たか」を後から比べられるようにするための場所です。

```text
experiments/
├── evaluation_plans/   # 評価計画(データの分け方・kの値)のJSON
├── records/            # 実験の記録(1実行1JSON。git管理外。.gitkeepのみ追跡)
└── recorder/           # 記録者のプログラム
    ├── evaluation_plan.py       # 評価計画のJSONを読んで検証する
    ├── data_splitter.py         # holdout / kfold でデータを分ける
    ├── cross_validator.py       # 分割ごとに学習・評価し、平均と標準偏差を出す
    ├── run_key.py               # 「同じ条件の実行か」を見分けるキー(ハッシュ)を作る
    ├── experiment_recorder.py   # 実験を実行して、records/ に書く
    └── record_reader.py         # 記録の一覧・詳細・同じ条件の検索
```

## 流れ
1. 選ぶ(フロントの「実験」、または `POST /api/experiments/run`): シナリオ・評価計画・パラメータの上書き・メモ
2. 実行キーを作る。同じキーの記録があれば、実行せずにその記録を返す(`force: true` で、もう一度実行する)
3. 評価計画に沿ってデータを分け、分割ごとに学習・評価する
4. 結果を `records/` に1ファイルで書く

交差検証は「この設定が良いか」を測るためのもので、予測用のモデルは作りません。
予測用のモデルを作る(データの7割で学習し、残り3割で評価して保存する)のは、`POST /api/train` です。

## 評価計画(evaluation_plans/*.json)
| 名前 | 内容 |
|---|---|
| `method` | `kfold`(k分割交差検証)か `holdout`(1回だけ分ける) |
| `k` | kfold の分割数(2以上の整数)。最も少ないラベルのサンプル数より大きいと、エラーになる |
| `stratified` | kfold で、ラベルの比率をそろえる(層化)か。既定 true |
| `test_ratio` | holdout で、評価に使う割合(0〜1の間) |
| `seed` | 乱数の種(同じ値なら、同じ分け方になる) |
| `description` | 画面に出す説明 |

- 通常データ(AEの学習用)とラベル付きデータ(SVM・クラスタリング用)は、別々に分ける
- 評価計画を足すときは、このフォルダにJSONを置くだけ(ファイル名が、計画の名前になる)
- TODO: 人・日ごとの `group_id` を同じfoldに入れる分割は、データ形式が決まってから対応する。
  サンプル単位でシャッフルすると、似たデータが学習側と評価側に混ざり、精度が高く出すぎることがある

## パラメータ
モデルの既定JSON → シナリオの `parameters` → 実行時の上書き、の順に重ねます。
既定JSONにない名前を上書きしようとすると、エラーになります。

## 実行キー
合成後のパラメータ・pipeline・評価計画・データファイルのハッシュから作ります(`1.0` と `1` は同じ値として扱う)。
パラメータ・評価計画・データのどれかが変われば、別の実行になります。

## 記録(records/*.json)
ファイル名は `YYYY-MM-DD-HHMMSS-<シナリオ>-<実行キー8文字>.json` です。

| 項目 | 内容 |
|---|---|
| `id` / `created_at` / `run_key` | 記録のID・日時・実行キー |
| `scenario` / `pipeline` | シナリオ名と、モデルの順番 |
| `parameters` | 実際に使った全パラメータ(既定値+上書き) |
| `evaluation_plan` | 使った評価計画 |
| `data` | データのハッシュ・件数(通常・ラベル付き)・特徴量の数・ラベルごとの件数 |
| `git_commit` | 実行時のコードのcommit |
| `folds` | foldごとの指標 |
| `summary` | 指標ごとの平均と標準偏差 |
| `seconds` | かかった時間 |
| `note` | メモ |

指標は、`3-Shared/concept/metrics.json` にある5つです(正解率・F1・乖離検出率・通常の誤検出率・サブタイプ分離)。

## 保存先
環境変数 `ML_RECORDS_DIR` で変えられます(テストや試し打ちで、本物の記録を汚さないため)。
